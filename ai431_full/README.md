# Independent full-benchmark AI-431-inspired variable pipeline

[PharmaSUG 2026 AI-431](https://pharmasug.org/proceedings/2026/AI/PharmaSUG-2026-AI-431.pdf), pages 2–4, motivates specification review, independent variable code generation, sandbox execution/error correction, QC and merge. This is independently written software, not authors' software or numerical reproduction. No author-supplied complete 13-dataset implementation was available. Existing human-approved benchmark specifications stay immutable. Per-dataset model reviews are advisory, retained but never fed to workers. Interactive human specification refinement and human clinical rescue are deliberately excluded.

## Fixed exploratory design

One new excluded attempt per planned endpoint: Anthropic Claude Sonnet 5.5, official Google Gemini 3.1 Pro Preview, official DeepSeek Flash, gateway-claimed Sol 6.1, and DeepInfra openai/gpt-oss-20b. Model strings are provider assertions, not independently authenticated fixed weights. Gateway results are never relabelled official OpenAI. Readiness uses synthetic inputs only; failed endpoints retain planned status and have no invented clinical outcomes. No model substitution, automatic transport retry or reuse of prior generated clinical programs/results.

All 13 datasets / 531 variables use the same new code version, approved source inputs, Docker image, three concurrent variable tasks, serial dataset/model execution, provider-default sampling/reasoning and 32768-token output/reasoning cap. Local code/QC errors permit two attempts total per task/export. No overall repair-time limit. API300-second and sandbox1800-second timeouts protect transport/process execution, not a repair-time allowance. Incomplete or tool-call replies are rejected and stop new requests. Pending tasks see the stop flag; in-flight evidence is retained.

The controller supplies ADSL's exact randomized subject keys, not target clinical values. Other datasets receive one generated row-universe task, returning subject identity plus optional scalar __SRC_* source/donor/derived-row identifiers; controller assigns stable __ROWID. Each independent variable sees only those row keys/helpers, frozen context and declared upstream datasets from the SAME run. It cannot see other current-dataset variable workers' programs/results. It recomputes intermediate values locally. Exact row-key/subject/order, variable ownership, type, finite numeric values and byte length are checked, then variables merge one-to-one by __ROWID and USUBJID. Selected merged consistency gates remain separate from comprehensive derivation correctness. The complete row-universe contract and automatic merge/failed-task policy are explicit benchmark adaptations.

Prompts include the assigned variable and recursively referenced same-dataset dependency specifications, every global rule/implementation detail, the current-dataset parameter map, value-level rows for selected variables and their referenced codelists. Row-universe tasks receive all current-dataset variables/value-level rows. All models use identical deterministic context selection. The complete unchanged specification remains readable at /inputs/specifications.json; this is input/context organization, not changed clinical logic. Dataset reviews receive all current-dataset variable specifications and global rules. Advisory review output is never applied.

Dataset dependency ordering is obtained from frozen source metadata, not the GxP process-node decomposition. GxP code is reused only for generic specification parsing, runtime/structural/export/evaluator helpers. A failed variable blocks that dataset merge and dependent datasets; unrelated work continues. A provider, invalid completion or controller error stops subsequent requests. Otherwise accepted complete dataset subsets can be exported; primary P21 score still requires complete 13-dataset coverage. Partial outputs do not count as full success. Model-generated exporter preserves all accepted values and creates XPT, Define-XML, metadata, manifest and notes. Reconstruction reruns accepted variable programs offline before strict semantic/byte comparisons. Terminal P21 results are never repair feedback. Selected NPI/TTE checks cannot certify all clinical values.

Character-null handling is fixed before this cohort: nullable strings preserve all-missing declared character values through JSON; SAS blanks at XPT serialization are specification-bound. No nonmissing or numeric values are filled/changed. Generated code has no network, credentials, reference outputs, evaluator or other-run access. No web/model tools are offered. All code, prompts, source files/schemas, provider identities, qualification, runtime image/cache and evaluator dependencies are hash-bound before generation in non-cloud directories. Full private evidence is losslessly archived with per-file stream-hash verification. Only aggregate results, code and hashes are published; never keys or clinical records.

Report all 19 existing metric labels, including failed calls' native tokens, review calls and local repairs. Native cache conventions are normalized explicitly; cached tokens are a subset of total input. Price metrics remain unavailable without verified billing. Tool-call metrics are N/A for direct APIs; sandbox counts are separate. No complete initial P21 baseline exists, so reduction/new-rule metrics are unavailable. One exploratory run, provider defaults, serial order and hosted aliases do not support causal/model/architecture-superiority claims. Historical GxP and ADSL outcomes and the formal main-study freeze are unchanged.

Commands: `python -m unittest ai431_full.test_pipeline`; `python -m ai431_full.readiness --out NEW_PRIVATE_DIR --env-file ../clinical_bench/.env.local --execute`; qualify the synthetic wrapper with `research_analysis.qualify_ai431_full`; prepare a NEW private root using `python -m ai431_full.run prepare-freeze --root ... --source VERIFIED_INPUT_ROOT --readiness ... --qualification ... --env-file ...`; execute with `python -m ai431_full.run run --root ... --env-file ... --execute`. Preserve every root and failure; any implementation change requires a new version/freeze.
