## Interpretation and provenance

Gemini AI-431 was explicitly rerun after API credit refill; its prior failed result remains in the table. It uses the same original frozen experimental implementation in a new root. The other three attempts use new provider-profile pins: official api.openai.com Responses for Sol and DeepInfra for gpt-oss-20b. New GxP attempts start from zero using the previously qualified nullable-character serialization boundary; no historical programs, responses or clinical outputs are reused. They differ from the historical original GxP code version and the historical Claude/DeepSeek engineering continuations. This is not a balanced or causal architecture comparison.

All attempts target the same 13 datasets/531 variables and use frozen inputs, original architecture prompts/QC, provider-default sampling, 32768 output/reasoning cap, two local attempts and original terminal P21/rebuild/auxiliary checks. AI-431 has three variable workers; GxP has two dataset branches. No web tools, credentials or network are available to generated code. No manual clinical repairs or automatic transport retries. P21 is never repair feedback. Missing results are not zero; partial outputs do not establish a full-coverage primary P21 score. Dollar costs remain unavailable without verified billing. Native output includes reasoning where reported; unknown cached usage stays unavailable.

Full clinical requests, outputs, programs and every failure remain private in verified lossless archives. Published records contain aggregates/code/hashes only. Follow-up-specific status, timing, token counts and failures are in each new summary; the original tables and original frozen evidence remain unchanged.
