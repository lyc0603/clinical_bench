## Interpretation

Both attempts use DeepInfra-hosted meta-llama/Llama-4-Scout-17B-16E-Instruct, not local inference. Provider assertions do not pin exact deployed weights. The independent adaptations target 13 datasets and 531 variables using the existing frozen inputs, prompts, gates, two attempts per task, provider-default sampling and 32,768 output-token cap. GxP uses two dataset branches; AI-431 uses three variable workers. No manual clinical repairs, prompt truncation, automatic transport retries or changes to clinical rules occurred. The main study has not started.

GxP was rejected on its first clinical API request because the service reported a 131,072 context limit. The reported input count of at least 98,305 is a lower bound, not exact token usage. Together with the 32,768 output reservation it exceeds that limit. This is an API/context compatibility outcome, not evidence of P21 failure or clinical derivation quality. Billed usage is unknown.

Failures and unavailable metrics remain in the denominator. These nonconcurrent, single-attempt observations do not establish causal architecture or model superiority. Historical engineering continuations remain explicitly labelled. Full requests, generated code, data and errors are retained privately in verified lossless archives; only aggregate metrics and provenance hashes are public. See each new summary for observed task counts, timing and token receipts.
