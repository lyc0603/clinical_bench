# Independent AI-431-inspired ADSL variable pipeline

This is an independent architectural adaptation of PharmaSUG 2026 AI-431, not original author software or numerical replication. [Paper](https://pharmasug.org/proceedings/2026/AI/PharmaSUG-2026-AI-431.pdf), pages 2–4: specification review and confirmation, independent variable generation, sandbox execution/error repair, QC and merging of accepted variables. No author code is copied.

## Frozen experimental design

One excluded ADSL-only exploratory attempt; 49 variables, exact GEN01 randomized subject keys. Claude Sonnet 5.5 direct Anthropic Messages API, fresh contexts, provider-default sampling/reasoning, max_tokens 32768. There are 49 independent variable tasks, at most three concurrent API/code tasks, at most two attempts per task, plus one advisory review and at most two export calls. No planning agent, multi-agent router or transfer of another worker's generated code. Each variable task receives source schemas, its specification and lexically selected dependency specifications, approved rules/implementation details/terminology. It recomputes needed intermediate values from source independently. No clinical derivation helper templates or reference ADaM are provided.

This is the post-confirmation code-generation/evaluation part of AI-431. Specifications have already been human-approved and frozen. A fresh model review is advisory, retained separately and does not modify the specification or condition worker prompts. It is not a reproduction of the paper's interactive specification-refinement lifecycle. No programmer changes specs or generated code after freeze; exhausted failures are measured, not manually rescued. These are deliberate adaptations for an automatic benchmark, not claims about the original system.

The controller supplies only a GEN01 subject-key dataframe (USUBJID), not derived target values. Every task must return exactly those unique keys plus its assigned variable. QC checks name/type, character byte length, exact subject identity, key uniqueness, ITTFL and records missing counts. Missingness is measured; there is no blanket nonmissing requirement for legitimately missing variables. QC-passed variables are merged one-to-one by USUBJID in specification order; it never concatenates rows by position. The merged frame undergoes existing cross-variable structural/duration/population checks. An exhausted variable blocks merge/export; remaining independent tasks may finish and are retained. Provider failures cancel pending tasks after already in-flight work returns; uncertain calls are never automatically retried. Provider timeouts are transport protection, not a repair-time budget.

A separate model export task receives the merged dataframe and exact delivery paths. It may create metadata, XPT, Define2.0.0, manifest and notes but may not change derived values. Define must be output/adam/datasets/define.xml with relative XPT href adsl.xpt. Controller packages accepted programs and deterministic key/merge/replay orchestration. Independent offline reconstruction precedes terminal P21 evaluation (ADSL-only expected set). P21 is not fed back to any worker. Selected direct-source checks are auxiliary and do not cover every clinical value.

## Runtime, privacy and reuse

Python/pandas/pyreadstat in the existing pinned Docker image. Generated code has no network or API key and cannot access evaluator, other runs or reference ADaM. Every attempt has its own workspace with copied source inputs, protected wrapper/programs and JSON artifacts; no pickle. Python -B suppresses import-generated bytecode so undeclared output-file gates remain meaningful. No arbitrary variable-written files are permitted. Code, inputs, runtime image, prompts, source schemas, P21 cache/support inputs and reused helpers are frozen. The GxP module is reused for input preparation, transport-independent parsing and existing checks only; its historical generated clinical programs and outputs are never consumed. Reused modules are hash-bound; the completed GxP run is unchanged.

Raw clinical inputs, generated programs, model requests/replies and reports remain local. Only aggregate measurements and evidence hashes may be published. Report review and failed-task token usage, not just accepted generation. Distinguish final package completion, structural coverage, semantic rebuild, byte equality, P21 usability and findings. A usable report does not imply zero findings or clinical correctness. Do not pool this one-dataset result with full-study 13/531 endpoints or infer architecture superiority from unmatched tasks or one run. Cost is unavailable without verified billing rates.

Run synthetic unit tests before preparation. Use `python -m ai431_adsl.run prepare-freeze --root NEW_PRIVATE_ROOT --env-file ../clinical_bench/.env.local`, then `python -m ai431_adsl.run run --root SAME_ROOT --env-file ... --execute`. Preparation is fail-if-existing. Never edit frozen code or overwrite prior runs. New implementation changes require a new freeze and clearly retained adjudication.

## Revision 2 — repair and new run

The first variable pipeline's 49 accepted variables remain retained. Its original packaging failed after workspace loss/conflict in the synchronized Desktop directory; a separately documented infrastructure continuation verified recovered evidence but its export reply stopped at max_tokens. Examination found 1448 lines of text including simulated bash/invoke tool syntax and repeated fictitious cat commands, not merely a necessary long metadata program. This does not justify accepting its truncated reply.

Revision 2 gives export its own tool-free system prompt, requires installed pyreadstat/lxml rather than a handwritten XPT serializer, requests compact loops that read frozen metadata at runtime, and sends a compact metadata context rather than derivation instructions. The output allowance remains 32768 and truncation is still rejected without automatic retry. Variable prompts now explicitly type inputs as pathlib.Path, never a mapping, addressing the prior 28 Path-vs-dict runtime failures. No clinical specification or value-generation code is supplied by the controller.

Actual execution uses a unique /private/tmp directory and archives completed/failed immutable evidence to the private root/run on termination; the local execution copy is retained. The run-location pointer permits auditing interrupted runs. Source inputs, code, prompts, model, configuration and storage policy are re-frozen before starting. All 49 variables and advisory review are generated again; no previous derived columns or programs are reused. This is a new development implementation and not a prespecified repeated measurement under version 1. Prior outcomes remain unchanged. Existing model-flagged specification/subset issues are not silently adjudicated by this controller repair.
