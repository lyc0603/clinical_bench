# Excluded Gemini temperature sensitivity pilot

Three fresh initial-only generations use the existing `google/gemini-3.1-pro-preview`, frozen study inputs, generation prompt, evaluator and clean-state P21 qualification. Temperatures are 0.2, 0.6 and 1.0, with one attempt each and fixed execution order 1.0, 0.2, 0.6. This is an exploratory sensitivity study, not the formal main study or a powered comparison. The mutable preview endpoint does not establish fixed model weights.

The only primary-agent sampling change is explicit temperature. Pinned OpenCode defaults remain topP 0.95, topK 64, high thinking and 32,000 maximum output tokens per model response, as verified by an offline request-capture test. The title helper is disabled consistently: the pinned runtime otherwise chooses a different small model for incidental title generation. Therefore historical default-setting controls are contextual, not concurrent matched temperature controls. No model subagents, web search or general web access is enabled. The original provider-only network policy remains enforced.

Before clinical generation, three tiny direct provider requests verify acceptance, an offline mock endpoint observes the exact generated request bodies with dummy credentials, and three real nonclinical OpenCode sessions demonstrate normal completion and tool use. Acceptance and serialization are observable; server-side sampling internals are not. The model, source input/evaluator seal, clean cache manifest, qualification receipts, extension code, sampling settings and order are frozen in a separate private lock. Never overwrite previous attempts or silently retry a failure.

[Google recommends temperature 1.0](https://ai.google.dev/gemini-api/docs/gemini-3#temperature), warning that lower temperatures can cause looping or degraded reasoning. This extension deliberately studies deviations. There is no agent time cap, consistent with the existing experiment; operational interruption must be documented and never relabeled as normal completion. P21/rebuild technical limits remain unchanged. No self-review or P21-feedback repair is run; reduction/new-finding repair metrics are N/A. All 16 original metrics are retained where applicable and missing results remain unavailable rather than zero.

Use `python -m temperature_extensions.gemini --help`. Credentials, raw histories, generated clinical artifacts and P21 reports remain outside Git. Publish only aggregate metrics and sanitized technical evidence. Prior reports are preserved. Any later merged table must distinguish one-shot temperature endpoints from historical paired or repaired endpoints and preserve all original records exactly.
