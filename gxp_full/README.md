# Full-benchmark Process-DAG exploratory extension

An independently designed extension of GxP-Agent's fixed-process decomposition to this benchmark's 13 ADaM datasets and 531 specified variables. The paper does not supply this complete 13-dataset DAG. This is not original author software or numerical replication; Python replaces R/pharmaverse. A new excluded exploratory attempt uses Claude Sonnet5.5 through official Anthropic Messages API, provider-default sampling/reasoning, max_tokens32768. It does not change the formal main-study freeze or the completed ADSL case studies.

## Fixed plan and controller contribution

The frozen `Datasets` source column determines cross-dataset edges: ADSL precedes all other datasets; ADLBHY also consumes accepted ADLBC; ADTTE also consumes accepted ADAE. Source order plus Build order provides a deterministic topological plan. ADSL retains 13 derivation/validation process nodes from the adapted ADSL design; per-dataset metadata/export is replaced by one combined package exporter. The other twelve datasets have five process nodes: complete record universe/source fields, subject covariates, numeric analysis quantities, flags/sequence, validation. Ownership is classified deterministically from the approved column names, origin source and types. Every one of 531 variables is assigned exactly once; no model plans/reassigns nodes. The full frozen `dag.json` lists every variable owner. Total: 73 process nodes plus one combined export task.

Only two independent dataset branches may run concurrently. Every process/export task permits two attempts. Provider failures stop new requests without automatic retries. Exhausted node failure blocks the dataset and descendants; unrelated branches may finish. If some datasets pass, the exporter may deliver that subset; the unchanged evaluator still expects all13 and reports missing coverage explicitly. Partial P21 counts are descriptive, not a primary complete-package result. No-data output is not accepted: all13 targets are required nonempty as a predeclared technical gate for this extension.

The record-universe node creates all expected original/derived/LOCF rows using the frozen algorithms; subsequent nodes cannot add/drop/reorder rows or alter earlier unowned values. Source selections may be recomputed internally where needed. This is a deliberate fixed row-contract adaptation; it may expose failures different from other architectures. Controller assigns an internal row ordinal only, not clinical values. Optional scalar source-donor helpers have __SRC_ names and are stripped before export. Only declared same-run upstream generated ADaM frames are exposed, not reference outputs or historical generated programs. No clinical answer templates, manually derived values or human code repairs are inserted.

## Context, QC and evaluation

All22 frozen SDTM domains, SAP and the complete specification (including all rule, implementation, parameter, value-level, windows, terminology and site tables) are copied unmodified. No ADSL-only subset with dangling references is used. Per-node prompts include the dataset's full specification and all approved rule/implementation tables; source schemas and declared upstream schemas are provided. Metadata/instructions in source documents are task data, not authorization to override controller policies. Clinical conventions stay frozen. No interactive specification changes or arbitrary clinical decisions occur during generation.

QC verifies exact ownership, expected types/character lengths, eligible subject identities, immutable row ordinals/earlier values, selected ADSL duration and ASEQ consistency. These are structural and limited business-rule gates, not comprehensive derivation correctness. The final exporter uses installed pyreadstat/lxml, reads metadata dynamically, writes 13 XPT plus combined Define2.0.0/metadata/manifest/notes at explicit paths and preserves data values. No tool-call markup or handmade XPT serializer is allowed. P21 findings never reach generation/repair.

Independent final evaluation reuses `main_experiment.evaluate.Evaluator` unchanged: complete deliverables and variable coverage, NPI/conditional TTE auxiliary checks, terminal clean-cache P21 and clean offline reconstruction. Complete and partial reports, zero findings and unavailable endpoints must remain distinct. No inference of architecture superiority or broad clinical correctness from one run. TTE auxiliary checks retain the existing conditional/source-flag limitations. Results are separate from the original18-workflow main-study allocations.

## Isolation, freezing and qualification

Generated code executes in the existing hash-pinned image, network none, no API credentials/evaluator/reference ADaM, dropped capabilities, 4cpu/8GiB per active container. Only selected source input copies and the current candidate work area with declared upstream frames are visible. Python -B prevents incidental bytecode files. JSON table intermediates avoid unsafe pickle. Model transport stays on the host using the authorized Anthropic key.

Use a unique non-cloud /private/tmp execution directory, retain it and archive immutable evidence once at termination. Never overwrite roots or modify frozen code in flight. Preparation freezes full source hashes, plan/ownership, model/prompts/wrappers, this package, reused transport/helpers/evaluator code, image, configuration, P21 cache/support files and matching nonclinical qualification. Source-code and input hashes are checked per attempt. Nonclinical synthetic node/upstream/row-ID and 13-dataset export qualification must pass before freezing.

Run `python -m unittest gxp_full.test_full` then `python -m gxp_full.run prepare-freeze --root NEW_PRIVATE_ROOT --env-file ../clinical_bench/.env.local --qualification RECEIPT`, followed by `run --root SAME_ROOT --env-file ... --execute`. Private base configuration/inputs and pinned runtime must already exist. Raw clinical artifacts and provider requests remain private. Only aggregate results and hashes may be published after review.

Before the first clinical freeze, one unstarted preparation failed while scanning TS.xpt because it contains Windows-1252 characters. Its partial root is retained. The revised preparation records each domain's read_encoding (TS cp1252, otherwise default) without modifying any source bytes. Only UnicodeDecodeError triggers this declared encoding fallback; other read failures propagate. The 30-test suite covers this boundary. No clinical generation occurred in the unstarted preparation.
