# Post-hoc node-boundary engineering continuation

The first DeepSeek full-DAG attempt passed five ADSL nodes, then failed twice on the controller's character-storage gate for DURDSGR1. The generated second-attempt program explicitly returned an object character container; its JSON schema declared string, but all values were null. Pandas inferred float on the next read. A synthetic reproduction confirms this controller/interface defect. It is not evidence that the model produced an incorrect nonmissing clinical value.

This separate continuation preserves every original failure. It uses nullable pandas string dtype for entirely missing character columns before node JSON serialization, retaining both character dtype and null semantics. Other character columns retain their original storage dtype. Nonmissing non-character values are rejected. Numeric columns are unchanged by normalization; existing JSON precision and original numeric comparison tolerance are retained. The inspection adapter avoids pandas' unsupported empty-string-series reduction without changing inspected values. The export serializer uses the same value policy with a compatible empty-series check. No evaluator or strict reproduction threshold changes.

The five accepted node programs and second duration candidate are reused byte-for-byte and reexecuted offline under the corrected wrapper, with zero new model calls for these six steps. Historical native receipts are copied with an explicit reuse marker and excluded from new-token totals. If a reused node still fails QC, stop rather than request a replacement for that accepted historical program. New generations start only at the next process node and follow the same provider, native model binding, prompts/full context, output cap32768, two-attempt local rule and terminal evaluator. No P21 findings enter repair prompts and no clinical code is hand-edited.

This is an explicitly post-hoc engineering continuation, not a clean same-version rerun or an additional independent repetition. Publish the original controller-blocked result and continuation status together. Gemini's original code/input-reading failure is retained. New controller changes must not be used to claim a matched model comparison. The formal main-study lock is unchanged.
